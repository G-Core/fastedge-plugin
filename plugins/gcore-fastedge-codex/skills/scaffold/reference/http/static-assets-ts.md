# Static Assets — TypeScript (HTTP)

Serve build-time-bundled static files (CSS, images, HTML templates) and JSX-rendered pages from a single FastEdge WASM binary. No external CDN, no separate origin required.

## When to Use

Use this blueprint when the user wants to:
- Serve a small static site (HTML/CSS/images/templates) from a single FastEdge WASM
- Mix static file serving with JSX-rendered or template-composed pages
- Inline HTML template strings into responses at the edge
- Bundle all assets at build time (no runtime file I/O)

## Files to Create

### Edge Handler Source

**`src/index.tsx`**
```tsx
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';
import { Hono } from 'hono';

import { staticAssetManifest as imagesStaticAssets } from './images-static-assets';
import { JsxContent } from './jsx-page';
import { staticAssetManifest as stylesStaticAssets } from './styles-static-assets';
import { staticAssetManifest as templatesStaticAssets } from './templates-static-assets';

const imagesStaticServer = createStaticServer(imagesStaticAssets, {
  routePrefix: 'images',
});

const stylesStaticServer = createStaticServer(stylesStaticAssets, {
  routePrefix: 'styles',
});

const templatesStaticServer = createStaticServer(templatesStaticAssets, {});

const app = new Hono();

app.get('/', async (c) => c.html(
    <html>
      <head>
        <title>Test Site</title>
        <link rel='stylesheet' href='/styles/index.css'></link>
      </head>
      <body>
        <h1>Home Page</h1>
        <p>Basic HTML rendering</p>
        <div class='nav-link'>
          <a href='/jsx'>Go to React JSX Page</a>
        </div>
        <div class='nav-link'>
          <a href='/template'>Template String Page</a>
        </div>
      </body>
    </html>,
  ));

app.get('/jsx', async (c) => {
  const props = {
    name: 'World',
    siteData: {
      title: 'Hello <> World',
      description: 'This is a description',
    },
  };
  return c.html(<JsxContent {...props} />);
});

app.get('/styles/*', async (c) => stylesStaticServer.serveRequest(c.req.raw));

app.get('/images/*', async (c) => imagesStaticServer.serveRequest(c.req.raw));

app.get('/template', async (c) => {
  const templateString = await templatesStaticServer.readFileString('/index.html');
  return c.html(templateString);
});

addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(app.fetch(event.request));
});
```

## Key API Patterns

### `createStaticServer`

```ts
import { createStaticServer } from '@gcoredev/fastedge-sdk-js';

const server = createStaticServer(staticAssetManifest, options);
```

**Parameters:**
- `staticAssetManifest` — object generated by `npx fastedge-assets`. Keys are asset paths; values contain `assetKey`, `contentType`, `isText`, `fileInfo`, `lastModifiedTime`, `type`.
- `options` — object:
  - `routePrefix?: string` — URL path prefix used when matching incoming requests (e.g. `'images'`, `'styles'`). Omit or pass `{}` for servers used via `readFileString` only.

**Returns:** static server instance with two consumption methods.

### Consumption Method 1: Serve as HTTP Route

```ts
// Mount as a catch-all Hono route
app.get('/styles/*', async (c) => stylesStaticServer.serveRequest(c.req.raw));
app.get('/images/*', async (c) => imagesStaticServer.serveRequest(c.req.raw));
```

- `serveRequest(request: Request): Promise<Response>`
- Use when a static asset class (CSS, images) should be accessible at a URL path.
- Pass `c.req.raw` (the native `Request`) rather than the Hono context.
- Returns a `Response` directly — return it from the Hono handler.

### Consumption Method 2: Read File Content Inline

```ts
// Read template file content and pass to c.html()
app.get('/template', async (c) => {
  const templateString = await templatesStaticServer.readFileString('/index.html');
  return c.html(templateString);
});
```

- `readFileString(path: string): Promise<string>`
- Use when composing a template string into a response rather than serving it as a direct download.
- `path` must match a key in the asset manifest (e.g. `'/index.html'`).

### JSX Rendering with Hono

Two rendering modes demonstrated:

**Inline JSX (component tree):**
```tsx
app.get('/jsx', async (c) => {
  return c.html(<JsxContent name="World" siteData={{ title: '...', description: '...' }} />);
});
```

**Template-literal layout (`hono/html`):**
```tsx
import { html } from 'hono/html';

const Layout = (props: SiteData) => html`
  <html>
    <head><title>${props.title}</title></head>
    <body>${props.children}</body>
  </html>
`;
```

Note from source: more elements slow down JSX, but not template literals — prefer `hono/html` template literals for large layout wrappers.

### Fetch Event Wiring

```ts
addEventListener('fetch', (event: FetchEvent) => {
  event.respondWith(app.fetch(event.request));
});
```

Standard FastEdge HTTP handler entry point. Wire after all routes are defined.

## Build Pipeline

The `build` script chains steps in sequence via `npm-run-all -s`:

1. `create-styles-manifest` — `npx fastedge-assets ./styles src/styles-static-assets.ts`
2. `create-images-manifest` — `npx fastedge-assets ./images src/images-static-assets.ts`
3. `create-templates-manifest` — `npx fastedge-assets ./templates src/templates-static-assets.ts`
4. `build:wasm` — `npx fastedge-build -i ./src/index.tsx -o ./dist/statics.wasm -t ./tsconfig.json`

The three `fastedge-assets` steps regenerate the `src/*-static-assets.ts` manifest modules from their companion source directories before compiling the WASM.

## Build Notes

### Binary assets gap (images)

The scaffold pipeline is markdown-oriented and does NOT ship binary files. The scaffolded project includes `src/images-static-assets.ts` with entries for `gcore.png` and `home.png`, but the `./images/` directory will be empty.

`npm run create-images-manifest` will fail unless the user addresses this. Two options:

1. **Populate `./images/`** — drop user-supplied PNG (or other image) files into `./images/` before running `npm run build`. The manifest will be regenerated from those files.
2. **Remove image serving** — if image serving is not needed, remove:
   - The `imagesStaticServer` instance and its import from `src/index.tsx`
   - The `app.get('/images/*', ...)` route from `src/index.tsx`
   - The `create-images-manifest` script from `package.json`
   - The `<img src='/images/home.png' />` reference in `src/jsx-page.tsx`
   - The `<img src="/images/gcore.png" />` reference in `templates/index.html`

### Generated asset modules are transient

`src/styles-static-assets.ts`, `src/images-static-assets.ts`, and `src/templates-static-assets.ts` are NOT hand-written files. They are shipped in the scaffold so TypeScript compilation and editor language servers succeed immediately (they reference real, valid manifests from the source example). However, `npx fastedge-assets` overwrites each of them on every `npm run build`.

**Edit the asset source directories** (`styles/`, `images/`, `templates/`), not the `*-static-assets.ts` files.

### TSX entry point

The build entry point is `src/index.tsx` (not `.ts`). `tsconfig.json` must include `"jsx": "react-jsx"` and `"jsxImportSource": "hono/jsx"` — both are present in the shipped config. Do not strip these.

## Route Summary

| Method | Path | Handler |
|---|---|---|
| GET | `/` | Inline JSX — returns HTML page with nav links |
| GET | `/jsx` | JSX component — renders `<JsxContent />` with `hono/html` layout |
| GET | `/styles/*` | `stylesStaticServer.serveRequest(c.req.raw)` |
| GET | `/images/*` | `imagesStaticServer.serveRequest(c.req.raw)` |
| GET | `/template` | `templatesStaticServer.readFileString('/index.html')` → `c.html()` |
