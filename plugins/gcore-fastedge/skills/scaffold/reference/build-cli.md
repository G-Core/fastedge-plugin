## fastedge-build CLI Reference

Compiles JavaScript or TypeScript source into a WebAssembly Component Model binary for deployment on FastEdge.

---

## Usage

```bash
# Direct mode
npx fastedge-build <input> <output>
npx fastedge-build src/index.js app.wasm

# Named flags
npx fastedge-build --input src/index.js --output app.wasm

# With TypeScript config (direct mode)
npx fastedge-build --input src/index.ts --output app.wasm --tsconfig tsconfig.json

# Config-driven mode
npx fastedge-build --config .fastedge/build-config.js
npx fastedge-build .fastedge/build-config.js  # single positional arg as config file
npx fastedge-build -c                         # uses default config path (.fastedge/build-config.js)
npx fastedge-build -c config1.js -c config2.js  # multiple configs, sequential

# Info
npx fastedge-build --help
npx fastedge-build --version
```

### Argument Rules

| Form | Interpretation |
| --- | --- |
| One positional argument | Config file path (config-driven mode) |
| Two positional arguments | `<input> <output>` (direct mode) |
| Options only, no positional arguments | Direct mode or config-driven mode |
| Positional arguments combined with options | Invalid; help is printed and exit code 1 |
| No arguments | Invalid; help is printed and exit code 1 |

- `--help` on its own prints help and exits with code 0. `--version` prints `@gcoredev/fastedge-sdk-js: <version>` and exits with code 0. If both are given, help takes precedence.
- Unrecognized flags are collected as positional arguments and subject to the rules above.
- If an option requiring a value is given without one (other than `-c`, which falls back to the default config path), help is printed and the CLI exits with code 0.
- In direct mode, both input and output paths must be supplied; otherwise help is printed and exit code is 1.
- If both an input/output pair and config files are supplied, the direct build runs and config files are ignored.

## CLI Flags

| Flag | Alias | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--input` | `-i` | `String` | — | Input JavaScript/TypeScript file (direct mode) |
| `--output` | `-o` | `String` | — | Output WebAssembly file path; must end in `.wasm` (direct mode) |
| `--tsconfig` | `-t` | `String` | — | Path to `tsconfig.json` for TypeScript check (direct mode only) |
| `--config` | `-c` | `String[]` | — | Path(s) to build config file(s); may be repeated |
| `--help` | `-h` | `Boolean` | `false` | Print usage help |
| `--version` | `-v` | `Boolean` | `false` | Print the SDK version |

- `--input` / `--output` are equivalent to positional arguments.
- A single positional argument is interpreted as a config file path (config-driven mode).
- `-c` given with no path uses `.fastedge/build-config.js`, relative to the current directory. This fallback applies to the short flag `-c` only. A bare `--config` with no path prints help and exits with code 0.
- `--tsconfig` is used only by the TypeScript check of the input file. esbuild bundles without it. It has no effect for `.js`, `.cjs`, and `.mjs` inputs, and is not read in config-driven mode — use `tsConfigPath` in the config file instead.
- `--input`/`--output` and `--config` are mutually exclusive modes. If both are provided, direct mode runs and config files are ignored.
- `--config` may be specified multiple times; configs are processed sequentially, each producing its own `.wasm` output.

## Config-Driven Builds

Use a config file (typically generated by `fastedge-init`) for projects requiring build type control or static site support.

### BuildConfig Interface

```typescript
interface BuildConfig {
  type?:          'http' | 'static';   // Required in config-driven mode; optional only when using direct CLI flags
  entryPoint:     string;              // required — input JS/TS file
  wasmOutput:     string;              // required — output .wasm path; must end in .wasm
  tsConfigPath?:  string;              // optional — path to tsconfig.json for TypeScript check
  // static-only fields (see Static-Only Fields section)
}
```

### BuildConfig Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `type` | `'http' \| 'static'` | Required in config-driven mode | Build type. Required in config-driven mode. Optional only when using `-i`/`-o` flags. If omitted or invalid in config mode, build exits with "Invalid config type". There is no default — it does not fall back to `'http'`. |
| `entryPoint` | `string` | Yes | Input JavaScript/TypeScript file |
| `wasmOutput` | `string` | Yes | Output `.wasm` file path; must end in `.wasm` |
| `tsConfigPath` | `string` | No | Path to `tsconfig.json` for the TypeScript check; not used by esbuild bundling |

**Note on `type`:** The TypeScript interface declares `type?` as optional because direct-flags mode never uses it. In config-driven mode, `type` is effectively required. If `type` is present but does not match `'http'` or `'static'`, the CLI prints `Error: Invalid config type. Must be one of: static, http.` and nothing is built for that config. If `type` is absent in config-driven mode, the build also errors — it does not fall back to `'http'`.

### Example Config — HTTP

```js
const config = {
  type: 'http',
  entryPoint: './src/index.js',
  wasmOutput: './dist/app.wasm',
  tsConfigPath: './tsconfig.json',  // optional
};

export { config };
```

### Example Config — Static Site

```js
const config = {
  type: 'static',
  entryPoint: '.fastedge/static-index.js',
  wasmOutput: '.fastedge/dist/fastedge.wasm',
  publicDir: './public',
  ignoreDotFiles: true,
  ignorePaths: ['/drafts'],
  ignoreWellKnown: false,
};

const serverConfig = {
  "type": "static",
  "extendedCache": [],
  "publicDirPrefix": "",
  "compression": [],
  "notFoundPage": "/404.html",
  "autoExt": [],
  "autoIndex": [
    "index.html",
    "index.htm"
  ],
  "spaEntrypoint": null
};

export { config, serverConfig };
```

The config file is an ES module that exports a named `config` object. When using a static entry file generated by `fastedge-init` (`.fastedge/static-index.js`), leave `assetManifestPath` at its default and export `serverConfig` from the same file. A partial `serverConfig` drops defaults such as `autoIndex`, so `/` stops serving `index.html`.

## Build Types

| Type | Description |
| --- | --- |
| `http` | Standard HTTP handler build. Runs esbuild → regex precompilation → Wizer → JCO. Produces a single `.wasm` component. |
| `static` | Generates an asset manifest from `publicDir`, embeds it, then runs the standard pipeline. |

Valid values are `'http'` and `'static'` exactly. Other values (e.g. `'http-handler'`, `'static-website'`) are invalid and produce an error.

---

## Static-Only Fields

These fields extend `BuildConfig` when `type` is `'static'`. They correspond to `Partial<AssetCacheConfig>` — all fields are optional at the type level.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `publicDir` | `string` | No | current directory | Directory containing static files to embed |
| `assetManifestPath` | `string` | No | `.fastedge/build/static-asset-manifest.js` | Output path for the generated asset manifest |
| `contentTypes` | `Array<ContentTypeDefinition>` | No | `[]` | Custom content type mappings (evaluated before defaults) |
| `ignoreDotFiles` | `boolean` | No | `true` | Skip files beginning with `.` |
| `ignorePaths` | `string[]` | No | `[]` | Paths to exclude from the manifest |
| `ignoreWellKnown` | `boolean` | No | `false` | Skip the `.well-known/` directory |

**`ignorePaths`** entries are paths relative to `publicDir`. Each entry is normalized to a leading `/` and matched exactly; globs are not supported. For example, `'/drafts'` excludes `<publicDir>/drafts`.

**`assetManifestPath`** — if the value does not end in `.js`, `.ts`, `.cjs`, or `.mjs`, `.js` is appended. If the resulting path is not a file path, a warning is printed and the default path is used. The generated manifest is overwritten on every build.

For `type: 'static'` builds, asset manifest generation is **automatic** — the build pipeline generates the manifest before compilation. The `fastedge-assets` CLI is only needed for standalone/manual manifest generation outside the build pipeline.

### ContentTypeDefinition

```typescript
interface ContentTypeDefinition {
  test:        RegExp | ((assetKey: string) => boolean);
  contentType: string;
  isText:      boolean;
}
```

Custom rules are evaluated before built-in defaults. Each rule matches asset paths via a `RegExp` or a predicate function.

## Build Pipeline Overview

For both direct and config-driven builds, the compilation pipeline executes these steps in order:

1. **Input validation** — input must be an existing file; output path must end in `.wasm`; output parent directory is created if it does not exist
2. **Syntax / type check** — `.js`/`.cjs`/`.mjs` files checked with Node; `.ts`/`.tsx`/`.jsx` files checked with the project's TypeScript (must be installed)
3. **esbuild** — bundles the JS/TS entry point into a single file; handles TypeScript transpilation if `tsConfigPath` is set
4. **Regex precompilation** — transforms Unicode regex patterns for compatibility with the SpiderMonkey engine
5. **Wizer** — pre-initializes the StarlingMonkey runtime with the bundled code
6. **JCO (componentNew)** — wraps the result into a WebAssembly Component Model binary
7. **Package metadata** (`addWasmMetadata`) — added to the component

For `type: 'static'` builds, asset manifest generation from `publicDir` is inserted before step 1.

### Environment Variables

| Variable | Type | Default | Description |
| --- | --- | --- | --- |
| `FASTEDGE_WIZER_PATH` | `string` | unset | Path to a wizer binary to use instead of the one from the `@bytecodealliance/wizer` package |

When `FASTEDGE_WIZER_PATH` is unset or empty, `fastedge-build` uses the binary from the `@bytecodealliance/wizer` package for the current platform. When set, that package is not loaded and the binary at the given path is used instead. Use this when building on a host OS different from where `node_modules` was installed (e.g., macOS install, Linux container build).

```bash
FASTEDGE_WIZER_PATH=/usr/local/bin/wizer npx fastedge-build src/index.js app.wasm
```

## Output

A successful build writes a `.wasm` file to the path specified by `wasmOutput` (config mode) or `--output` (direct mode). The output is a **WebAssembly Component Model** binary compatible with the FastEdge runtime.

**Success messages:**

- Direct mode:
  ```
  Build success!!
  "<input>" -> "<output>"
  ```
- Config mode (one line per config file):
  ```
  Success: Built <wasmOutput>
  ```

### Failure Output

A failed build can leave a file at the output path. Wizer writes the requested output file before the component creation and metadata steps run, so a failure in a later step can leave a partial `.wasm` at that path. Check the exit code and printed messages — do not treat file presence as a sign of success.

**Common failure messages:**

- Input is not a file: `Error: Input "<input>" is not a file`
- Output does not end in `.wasm`: `Error: Output "<output>" must be a .wasm file path`
- Input syntax or type errors: `SyntaxError: Javascript code` or `SyntaxError: Typescript code`, followed by checker output and `Error: "<input>" contains JS errors` or `Error: "<input>" contains Typescript errors`
- Unsupported input extension: `Error: "<input>" is not a valid file type - must be ".js" or ".ts"`
- TypeScript not installed: `TypeScript is not installed.` followed by `Please run "npm install typescript"`
- Wizer fails: `Error: Failed to compile JavaScript to Wasm: Wizer initialization failure`
- Config file not found: `Error: Config file not found at <path>. Skipping file.`
- Config `type` missing or invalid: `Error: Invalid config type. Must be one of: static, http.`

### Exit Codes

| Mode | Situation | Exit code |
| --- | --- | --- |
| Direct | Build succeeds | `0` |
| Direct | Validation, syntax check, or Wizer failure | `1` |
| Direct | Input or output path missing (help printed) | `1` |
| Direct | Component creation or metadata failure | Non-zero (error thrown) |
| Config | Every config file processed | `0` |
| Config | Config skipped (file not found or invalid `type`) | `0` (unchanged) |
| Config | Validation, syntax check, or Wizer failure | `1` immediately; remaining configs not processed |
| Config | Component creation or metadata failure | Non-zero (error thrown) |
| Config | Config file fails to import | Non-zero (error thrown) |
