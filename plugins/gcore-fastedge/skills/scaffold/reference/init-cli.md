# fastedge-init CLI

Interactive scaffolding wizard for FastEdge applications. Generates build configuration and starter files. No flags — all configuration is collected via prompts.

## Usage

```bash
npx fastedge-init
```

Run from the root of your project directory. `fastedge-init` is a wizard, not a one-shot command — it collects all configuration interactively.

If `.fastedge/build-config.js` already exists, the tool warns and prompts to overwrite. The confirmation defaults to `No`: answering `N` or pressing Enter exits without changes.

When a prompt receives invalid input (see validation columns below), the tool prints an error and exits with a non-zero status. The exception is the SPA entrypoint prompt, which prints a warning and continues.

### Application Type Selection

The first prompt asks what you are building:

| Option | Description |
|---|---|
| `Http event-handler` | A request/response handler compiled to WASM |
| `Static website` | A static file server with assets embedded in WASM |

## HTTP Handler Setup

### Prompts

| Prompt | Default | Validation |
|---|---|---|
| Path to your entry file | `src/index.js` | File must exist |
| Path to your output file | `.fastedge/dist/main.wasm` | Must end with `.wasm` |

### Files Created

| File | Purpose |
|---|---|
| `.fastedge/build-config.js` | Build and server configuration module |

### Generated Config

`.fastedge/build-config.js` exports two named objects using values from the prompts. Keys and string values are double-quoted (JSON style):

```js
const config = {
  "type": "http",
  "tsConfigPath": "./tsconfig.json",
  "entryPoint": "src/index.js",
  "wasmOutput": ".fastedge/dist/main.wasm"
};

const serverConfig = {
  "type": "http"
};

export { config, serverConfig };
```

#### Build Config (`config`)

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | `string` | `"http"` | Build type identifier |
| `tsConfigPath` | `string` | `./tsconfig.json` | Path to TypeScript configuration |
| `entryPoint` | `string` | `src/index.js` | Path to your entry file |
| `wasmOutput` | `string` | `.fastedge/dist/main.wasm` | Output path for the compiled WASM file |

### Entry File Requirements

The entry file must register a `fetch` event listener at the top level:

```js
async function handleRequest(event) {
  return new Response('Hello from FastEdge!', {
    headers: { 'Content-Type': 'text/plain' },
  });
}

addEventListener('fetch', (event) => {
  event.respondWith(handleRequest(event));
});
```

## Static Website Setup

`.fastedge/static-index.js` is written before the prompts are shown. The remaining files are written after all prompts are answered.

### Prompts

| Prompt | Default | Validation |
|---|---|---|
| Path to your output file | `.fastedge/dist/fastedge.wasm` | Must end with `.wasm` |
| Path to your public directory | `./build` | Directory must exist and not be empty |
| Is your site a single page application? | `No` | — |
| Path to your SPA entrypoint *(SPA only)* | `./index.html` | Warns if file is not found in, or resolves outside, the public directory |

For a single page application, the entered path is resolved against the public directory. The file must exist and must lie inside the public directory, both as typed and after symbolic links are resolved. If it does not, a warning is printed and `spaEntrypoint` is left as `null`. Otherwise `spaEntrypoint` is set to the asset key of the file: its path relative to the public directory, normalized with a leading `/` (for example, `./index.html` becomes `/index.html`).

### Files Created

| File | Purpose |
|---|---|
| `.fastedge/static-index.js` | Generated entry file — wires static server together; do not edit manually |
| `.fastedge/build-config.js` | Build and server configuration module |
| `.fastedge/package.json` | Marks `.fastedge/` as an ES module project |
| `.fastedge/jsconfig.json` | Sets compiler target to ES2023 for the project directory |

### Generated Entry File

`.fastedge/static-index.js` is generated automatically and must not be edited manually:

```js
/*
 * Generated by @gcoredev/FastEdge-sdk-js fastedge-init
 */

import { createStaticServer } from "@gcoredev/fastedge-sdk-js";
import { staticAssetManifest } from "./build/static-asset-manifest.js";
import { serverConfig } from "./build-config.js";

const staticServer = createStaticServer(staticAssetManifest, serverConfig);

async function handleRequest(event) {
  const response = await staticServer.serveRequest(event.request);
  if (response != null) {
    return response;
  }

  return new Response("Not found", { status: 404 });
}

addEventListener("fetch", (event) => event.respondWith(handleRequest(event)));
```

The asset manifest imported by this file is generated by `fastedge-build` during the build.

### Generated Project Files

`.fastedge/package.json`:

{

  "type": "module"

`.fastedge/jsconfig.json`:

### Generated Config

`.fastedge/build-config.js` exports two named objects using values from the prompts. Keys and string values are double-quoted (JSON style):

```js
const config = {
  "type": "static",
  "entryPoint": ".fastedge/static-index.js",
  "ignoreDotFiles": true,
  "ignorePaths": [
    "./node_modules"
  ],
  "ignoreWellKnown": false,
  "tsConfigPath": "./tsconfig.json",
  "wasmOutput": ".fastedge/dist/fastedge.wasm",
  "publicDir": "./build"
};

const serverConfig = {
  "type": "static",
  "extendedCache": [],
  "publicDirPrefix": "",
  "compression": [],
  "notFoundPage": "/404.html",
  "autoExt": [],
  "autoIndex": [
    "index.html",
    "index.htm"
  ],
  "spaEntrypoint": null
};

export { config, serverConfig };
```

For a SPA whose entrypoint exists in the public directory, `spaEntrypoint` is set to the asset key of that file (for example, `"/index.html"`) instead of `null`.

### Config Fields

#### Build Config (`config`)

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | `string` | `"static"` | Build type identifier |
| `entryPoint` | `string` | `.fastedge/static-index.js` | Path to generated entry file |
| `wasmOutput` | `string` | `.fastedge/dist/fastedge.wasm` | Output path for compiled WASM |
| `publicDir` | `string` | `./build` | Directory containing static assets to embed |
| `tsConfigPath` | `string` | `./tsconfig.json` | Path to TypeScript configuration |
| `ignoreDotFiles` | `boolean` | `true` | Exclude dot files and directories (except `.well-known`) |
| `ignorePaths` | `string[]` | `["./node_modules"]` | Paths relative to `publicDir` to exclude; matched exactly |
| `ignoreWellKnown` | `boolean` | `false` | When `true`, excludes the `.well-known/` directory |

`ignorePaths` entries are relative to `publicDir` and are matched exactly against the path of a file or directory, written with a leading `/` (for example, `/drafts`). Glob patterns are not supported.

#### Server Config (`serverConfig`)

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | `string` | `"static"` | Server type identifier |
| `extendedCache` | `Array<string \| RegExp>` | `[]` | Paths or patterns served with extended caching |
| `publicDirPrefix` | `string` | `""` | Prepended to the asset key after `routePrefix` is stripped |
| `routePrefix` | `string` | — | Stripped from the request path; not written by init |
| `compression` | `string[]` | `[]` | Accepted but has no effect; content encoding is not implemented |
| `notFoundPage` | `string \| null` | `"/404.html"` | Asset path served with status 404 |
| `autoExt` | `string[]` | `[]` | Extensions tried after a direct miss |
| `autoIndex` | `string[]` | `["index.html", "index.htm"]` | Index filenames tried when resolving a directory path |
| `spaEntrypoint` | `string \| null` | `null` | Asset path served for unmatched HTML requests |

`fastedge-init` does not write `routePrefix`; add it to `serverConfig` manually if needed. The generated file is plain JavaScript, so `extendedCache` entries added by hand can also be `RegExp` objects.

#### Server Config Behaviour

For each `GET` or `HEAD` request, the server resolves the asset key from the request path in this order:

1. `routePrefix`, if set, is stripped from the request path.
2. `publicDirPrefix`, if non-empty, is prepended to the result.
3. A leading `/` is added if missing.

The server then looks for a matching asset:

- A path that does not end in `/` is looked up directly. If there is no direct match, each `autoExt` extension is appended in turn. `autoExt` applies to any path not ending in `/`, whether or not the path already has an extension.
- If no asset has matched, the path is treated as a directory and each `autoIndex` filename is tried in order.

Other behaviour:

- `extendedCache` entries are matched against the request path. An entry is one of:
  - An exact path, such as `'/logo.png'`
  - A path prefix: an entry ending in `/`, such as `'/assets/'`, matches any path starting with it; `'/'` matches every path
  - A `RegExp` object
  - A `regex:/pattern/flags` string, such as `'regex:/\\.(js|css)$/i'`; other `regex:` forms are dropped with a warning

  Matching assets are served with `Cache-Control: max-age=31536000`.

- `compression` is accepted but has no effect. Content encoding is not implemented; assets are always served unencoded regardless of the `Accept-Encoding` header.

- When no asset matches and the request accepts `text/html`, the server serves `spaEntrypoint` (status 200, `Cache-Control: no-store`) if it is set and the asset exists. Otherwise it serves `notFoundPage` (status 404, `Cache-Control: no-store`) if it is set and the asset exists. Both values are asset keys, not paths relative to the public directory.

- An unset `notFoundPage` or `spaEntrypoint` normalizes to `'/'`, which matches no asset, so the feature is effectively off.

- Requests that the server does not handle — such as non-`GET`/`HEAD` methods, unmatched requests that do not accept `text/html`, or unmatched HTML requests when neither `spaEntrypoint` nor `notFoundPage` resolves to an asset — fall through to the `Not found` 404 response in the generated entry file.

## Generated Files Summary

| File | App Type | Purpose |
|---|---|---|
| `.fastedge/build-config.js` | HTTP + Static | Build and server configuration; exports `config` and `serverConfig` |
| `.fastedge/static-index.js` | Static only | Generated entry file using `createStaticServer`; do not edit manually |
| `.fastedge/package.json` | Static only | ES module marker for `.fastedge/` directory |
| `.fastedge/jsconfig.json` | Static only | ES2023 compiler target for `.fastedge/` directory |

## Post-Scaffolding

### HTTP handler

```bash
npx fastedge-build --config .fastedge/build-config.js
```

### Static site

```bash
npx fastedge-build --config .fastedge/build-config.js
```

The asset manifest is generated automatically when building with `type: 'static'`. No manual asset generation step is required. Run the same command again whenever your static assets change.
